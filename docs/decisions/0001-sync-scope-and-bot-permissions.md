# 0001: 同期の範囲と、bot の権限の持ち方

- 日付: 2026-11-09
- 状態: 採用中（方針を変えたら、このファイルは書き換えず、新しい ADR を作ってここを「廃止（NNNN で置き換え）」にする）
- 関連: Neplector の [ADR 0026](../../../Neplector/docs/decisions/0026-services-off-machine-own-bots-api-only.md) 判断1（サービスの bot には見る権限を付けない）、[0035](../../../Neplector/docs/decisions/0035-one-community-across-servers-and-sync.md)（同期はサービス）、[0040](../../../Neplector/docs/decisions/0040-read-whole-categories-and-forward-contents.md) の未決定（同期サービスの bot の権限）

## 判断1: bot に、同期カテゴリの中だけ見る権限を付ける（発案者）

**決めたこと**：同期カテゴリの中に限って、bot に見る権限と、チャンネル・Webhook・スレッドを管理する権限を付ける。発言の知らせを受ける常時接続（Gateway）は使わず、本文を読む特権（Message Content）も有効にしない。発言の情報はすべて Neplector の API から得る。

**検討した選択肢**：

- 案A（採用）：カテゴリ限定で許可する。構造を自動で同期でき、発言の知らせは受けない作りなので、外れた人の発言も届かない
- 案B（却下）：見る権限を付けない。原則どおりだが、チャンネルと Webhook を運営者が毎回手で作ることになり、構造の自動同期という目的を果たせない

**選んだ理由**：原則の目的は「外れた人の発言が bot に届かないこと」。発言の知らせを受けなければ、見る権限があってもその目的は守れる。Neplector の説明にある「どうしても要るときは運営者に相談」は、発案者が運営者として判断した。

**引き換え**：bot の token が漏れると、そのカテゴリのチャンネルを操作できてしまう。

**後で見直す条件**：リアクションの同期を作るとき。発言履歴を読む権限が追加で要る（Message Content が無いので本文は届かない想定）。

## 判断2: チャンネルが消されたら、相手側も自動で消す（発案者）

**決めたこと**：同期中のチャンネルが消されたら、相手側のチャンネルも履歴ごと消す。

**検討した選択肢**：

- 案A（採用）：相手側も消す。両方のサーバーの構造が常に同じになる
- 案B（却下、Claude の推奨）：消さずに同期を切り、運営者に知らせる。誤削除に強いが、構造がずれたまま残る
- 案C（却下）：保管用のカテゴリに移す。残せるが、カテゴリが1つ増える

**Claude が足した守り**（判断は変えず、誤作動だけを防ぐ）：

- `channel.delete` のときだけ動く。`channel.stop`（読むのをやめた、カテゴリの外へ移した）では消さない
- 消す前に、bot で元のチャンネルを Discord に聞き、404 のときだけ消す。403（権限が無い）や通信の失敗では消さない
- 1時間に3つを超えたら止めて、運営者の確認を待つ。カテゴリの一括削除やアカウントの乗っ取りで、相手の履歴まで全部消えるのを防ぐ。上限は設定で変えられる

**引き換え**：誤って消すと、両方のサーバーの履歴が失われ、元に戻せない。Discord の管理者が消せる人を絞る。

## 判断3: 構造は権限を除く見た目の設定まで同期する（発案者）

**決めたこと**：作成・削除・名前・カテゴリ名に加えて、トピック・並び順・低速モード・年齢制限・フォーラムのタグを同期する。権限は同期しない。

**検討した選択肢**：

- 案A（採用）：見た目の設定まで。使う人から見て同じ場所に見える
- 案B（却下）：名前と作成だけ。単純だが、トピックや並び順がずれる
- 案C（却下）：権限も含める。ロールはサーバーごとに別物で、見える範囲が意図せず広がるおそれがある。`Manage Roles` という強い権限も要る

**作り方**：トピックや並び順は Neplector の `channels` の表に無く、変わっても知らせが来ない。そこで bot が Discord から読み、数分おきに見回る。

## 判断4: カテゴリ自体は運営者が両方のサーバーに作る（Claude の案。判断1から決まる）

**決めたこと**：サービスはカテゴリを作らない。運営者が両方のサーバーに同じ名前のカテゴリを作り、bot の権限を付ける。そのあとの中身とカテゴリ名の変更は自動で同期する。

**選んだ理由**：bot の権限をカテゴリに限るには、そのカテゴリが先に無いといけない。サーバー全体の権限を bot に渡さずに済み、Neplector の設定（`category_ids`）にも運営者がカテゴリの ID を書く必要があるので、手間はここにまとまる。

**検討した選択肢**：

- 案A（採用）：運営者が作る
- 案B（却下）：bot がカテゴリも作る。サーバー全体の `Manage Channels` が要り、判断1と合わない。作ったカテゴリは全員に見えるので、意図せず公開するおそれもある

**後で見直す条件**：同期するカテゴリが増えて、手間が目立ってきたとき。

## 判断5: 最初の版は発言の基本一式まで（発案者）

**決めたこと**：発言・編集・削除、名前とアイコン、画像と動画、引用形式の返信、スレッドとフォーラム、外れた人の写しの削除まで。リアクションと投票は次の版にする。

**検討した選択肢**：

- 案A（採用）：基本一式。まず会話が通じることを確かめられる
- 案B（却下）：リアクションも含める。カスタム絵文字の対応付けと追加の権限が要る
- 案C（却下）：投票も含める。票を統合できず、合計の発言を更新する仕組みが要るので、いちばん作る量が多い

**後で見直す条件**：基本一式が本番で安定したら、リアクションから足す。本番ではリアクションの69%がカスタム絵文字（Neplector の [service-gaps](../../../Neplector/docs/design/service-gaps.md)）なので、絵文字の対応付けが中心になる。

## 判断6: bot に「メッセージの管理」を付けない（Claude の案。発案者の了承待ち）

**決めたこと**：写しの編集と削除は、投稿した Webhook の token で行う。フォーラムの投稿やスレッドごと消すときは「スレッドの管理」で足りる。人の発言は、どちらのサーバーでも bot が消さない。

**検討した選択肢**：

- 案A（採用）：付けない。token が漏れても、カテゴリの発言を消されない
- 案B（却下）：付ける。写しが消されたら元の発言も消せる。Webhook が消されたあとも古い写しを消せる。ただし、片方のサーバーの操作で相手の人の発言が消え、token が漏れたときの被害も大きくなる

**引き換え**：同期用の Webhook が消されると、それまでの写しを bot から消せなくなる。外れた人の写しを消せないときは、運営者に知らせて手で消してもらう。

**後で見直す条件**：Webhook が消される事故が実際に起きたとき。写しの削除を元の発言にも反映したくなったとき。ピン留めを同期するとき（そのときに要る権限を確かめる）。

## 用語メモ

- Webhook：チャンネルに投稿するための専用の URL。投稿ごとに名前とアイコンを変えられる
- Gateway：Discord と bot のあいだの常時接続。発言などの知らせはここに届く。使わなければ知らせは届かない
- Message Content：bot が発言の本文を受け取るための特権。有効にしなければ本文は届かない
- 404 / 403：Discord の答えの番号。404 は「無い」、403 は「権限が無い」
