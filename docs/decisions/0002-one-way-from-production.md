# 0002: 動作確認は本番のカテゴリから実験用のサーバーへの一方通行で行い、本番には見る権限だけを付ける

- 日付: 2026-11-09
- 状態: 廃止（[0003](0003-two-sites-and-always-on.md) で置き換え）
- 関連: [0001](0001-sync-scope-and-bot-permissions.md)、Neplector の ADR 0035（同期）、0042（告知）

## 判断1: test カテゴリで双方向を試さず、本番のカテゴリから一方通行で試す（発案者）

**決めたこと**：同期の元を本番の `Nep共同企画`、写し先を実験用のサーバーの同じ名前のカテゴリにする。実験用のサーバーは Neplector が読まないので、向きは本番から実験用への一方通行になる（設定 `direction = "a_to_b"`）。

**検討した選択肢**：

- 案A（採用）：本番のカテゴリから一方通行。Neplector の設定を変えずに、本物の発言の流れで確かめられる
- 案B（却下）：`test` を Neplector に読ませて双方向。実験用のサーバーの名簿まで記録することになり、Neplector の設定も変える
- 案C（却下）：偽の Neplector だけ。自動テストと実機の確認には使ったが、本物の発言の流れを確かめられない

**引き換え**：

- 本番の会話が実験用のサーバーに写る。告知の「もう一つの拠点」には当たらないので、見られる人を発案者が確かめて判断する
- 写しの投稿が Neplector で `counted = 0` になること、輪にならないこと、実験用から本番への流れは、実物では確かめられない。第二拠点で始めるときに確かめる

## 判断2: 一方通行のあいだ、本番の bot の権限は見るだけにする（Claude の案）

**決めたこと**：本番の `Nep共同企画` には View Channel だけを付ける。写し先のカテゴリには6つの権限を付ける。

**選んだ理由**：コードの作りだけでなく、Discord の権限でも本番を書き換えられなくなる。不具合があっても、本番のチャンネルは消えない。`doctor` は、書かない側に余分な権限があると問題として出す。

**検討した選択肢**：

- 案A（採用）：見るだけ。読むのに要るのはこれだけ
- 案B（却下）：`test` と同じ6つの権限。一方通行では使わず、不具合や token の漏洩で本番のチャンネルを消される危険だけが増える

**後で見直す条件**：双方向に切り替えるとき。そのときは本番にも6つ要る。

## 用語メモ

- 一方通行（`a_to_b`）：a の変更だけを b に流す。b で何が変わっても a には書かない
