# 0003: 2つの拠点の双方向に切り替え、常時動かす

- 日付: 2026-11-10
- 状態: 採用中（方針を変えたら、このファイルは書き換えず、新しい ADR を作ってここを「廃止（NNNN で置き換え）」にする）。判断3 のうち「移す先は Linux の systemd」は、[0013](0013-move-to-container-in-vm.md) で置き換え（移す先は IdeaPad の VM の中のコンテナ。`deploy/nepsync.service` は消した）
- 関連: [0001](0001-sync-scope-and-bot-permissions.md)、[0002](0002-one-way-from-production.md)（一方通行。この ADR で置き換え）、Neplector の ADR 0026（サービスは機械の外）・0035（同期）

## 判断1: KGU_Neptunity と CID_Neptunity を双方向にする（発案者）

**決めたこと**：同期の相手を実験用のサーバーから CID_Neptunity に替え、`direction = "both"` にする。実験用のサーバーへの同期は切る。

両方の拠点に告知が出ていて、Neplector が CID の `Nep共同企画` を読む設定になり、bot の権限（6つ）も両方のカテゴリに付いたので、始められる。

**ADR 0002 からの変更**：本番の bot の権限は、見るだけから6つになる。双方向では本番にも書くため。

**対応表は新しくする**：相手のサーバーが変わるので、`data/nepsync.db` を `data/nepsync-neo.db` に残して、空から始める。読む位置も今からになるので、始める前の発言は流れない。

## 判断2: CID の既存の `🫶｜学校間交流会` は移さない（発案者）

**決めたこと**：CID の `インフォメーション` にある同じ名前のチャンネルは、いずれ発案者の側で消す。`Nep共同企画` の中には、新しく同じ名前のチャンネルを作って KGU のものと組にする。

**検討した選択肢**：

- 案A（採用）：新しく作り、古いものは後で消す。発案者の判断
- 案B（却下、Claude の推奨）：古いものを `Nep共同企画` へ移して組にする。CID の履歴が同じ場所に残るが、見える範囲が変わることがあり、そもそも消す予定なので要らない

**引き換え**：消すまで、CID に同じ名前のチャンネルが2つある。組になるのは同じカテゴリの中だけなので、古いほうを消しても KGU のチャンネルは消えない（テストで確かめた）。

## 判断3: 常時動かす。今は Windows のタスク、移す先は Linux の systemd（発案者）

**決めたこと**：今はタスクスケジューラの「NepSync\run」で動かす。5分ごとに見回り、止まっていたら起こす。Linux に移すときは `deploy/nepsync.service` を使う。手順は [design/operations.md](../design/operations.md)。

**検討した選択肢**：

- 案A（採用）：Neplector と同じ形。覚えることが1つで済み、移す手順もそろう
- 案B（却下）：Windows のサービスとして登録する。ログインしていなくても動くが、管理者の権限と別の道具が要り、Linux に移すと捨てることになる。Neplector がログイン中しか動かないので、NepSync だけ動いても同期できない

**Linux に移しやすくするために決めたこと**：

- 場所に依存しない：パスはプログラムの場所から決める。OS で違うのは起動の設定だけ
- 標準のライブラリだけで動かす
- 2つ動かさない鍵は SQLite で取る（Neplector と同じ。どちらの OS でも、プロセスが終われば外れる）
- 動いている状態は `.env`、`data/nepsync.toml`、`data/nepsync.db` の3つだけ。これを写せば続きから動く
- API の住所は `.env` だけで変えられる

**引き換え**：ログインしているあいだだけ動く。PC を落とすと両拠点の同期が止まる。再開すれば続きから流れる。

**後で見直す条件**：Neplector の API を公開して Linux へ移すとき。

## 判断4: 想定していない失敗でもプロセスを落とさない（Claude の案）

**決めたこと**：権限の問題や想定していない失敗では、落ちずに運営者に知らせて、同じ行からやり直す。構造の見回りが失敗しても、発言の同期は止めない。ログには失敗の種類と場所だけを書き、値は書かない（本文が混ざらないように）。

**選んだ理由**：常時動かすと、見ている人がいないあいだに起きる。落ちて起こされることを繰り返すと、知らせも出ないまま止まって見える。

## 用語メモ

- systemd：Linux で、プログラムを動かし続ける標準の仕組み
- タスクスケジューラ：Windows で、決まった時やログインのときにプログラムを動かす仕組み
