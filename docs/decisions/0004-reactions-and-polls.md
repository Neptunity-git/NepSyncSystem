# 0004: リアクションと投票の同期

- 日付: 2026-11-10
- 状態: 一部置き換え（判断4 の「1分に1回」は [0011](0011-faster-tally-and-voters-menu.md) 判断1 で10秒に1回に置き換え。ほかは採用中）
- 関連: [0001](0001-sync-scope-and-bot-permissions.md) 判断1・5、Neplector の ADR 0040 の未決定（同期サービスの bot の権限）、[service-gaps](../../../Neplector/docs/design/service-gaps.md)

## 判断1: bot に、同期カテゴリの中だけ履歴を読む権限とリアクションの権限を足す（発案者）

**決めたこと**：両方の `Nep共同企画` で、bot に Read Message History と Add Reactions を許可する。

**検討した選択肢**：

- 案A（採用）：付ける。Discord の決まりで、リアクションを付けるのに要る
- 案B（却下）：付けない。投票だけになり、リアクションが同期できない

**選んだ理由**：Message Content が無効なので、Discord の資料では本文・添付は空で届く。発言の知らせを受けない作りも変えない。コードは履歴を読む窓口を呼ばない。

**引き換え**：token が漏れると、そのカテゴリの発言の書き手と時刻は読める。

## 判断2: リアクションは「今の姿をそろえる」形で写す（Claude の案）

**決めたこと**：リアクションの変更を受けたら、元と写しの両方の人のリアクションを Neplector で見て、bot の分を足し引きする。bot は1つの絵文字に1回なので、人数は同じにならない。bot が付けたものは ID と絵文字だけ控える。

**検討した選択肢**：

- 案A（採用）：今の姿をそろえる。構造の同期と同じ。取りこぼしても次で直る。誰かがまとめて消しても直る。外れた人の分は Neplector が `reaction.remove` を出すので、そのまま消える
- 案B（却下）：知らせを1つずつ写す。全員が外したかどうかを別に数える必要があり、順番がずれると直らない

**輪にならない理由**：Neplector は bot のリアクションを記録しない（`gateway_events.py`）。

## 判断3: 相手に同じ名前が無いカスタム絵文字は、写さずに知らせる（発案者）

**決めたこと**：カスタム絵文字は名前で対応させる。無いものは写さず、運営者に知らせる。相手に同じ名前で登録されたら、次の変更から写る。

2026-11-10 時点で KGU 45個・CID 44個のうち、43個は同じ名前。

**検討した選択肢**：

- 案A（採用）：写さずに知らせる。権限が増えず、いちばん単純
- 案B（却下）：元の絵文字をそのまま使う。Use External Emojis が要る
- 案C（却下）：bot の絵文字として登録する（最大2000個）。画像の取得と登録を作ることになる

## 判断4: 投票は両方に作り、合計を別の発言で更新する（発案者）

**決めたこと**：投票を相手にも Webhook で作る。両方のチャンネルに「投票の合計」の発言を1つずつ出し、票が変わったら書き換える（1つの投票につき最大で1分に1回）。締め切りを過ぎたら最後に1回書いて終わる。

- 書くのは選択肢ごとの票の数だけ。誰が投票したかは書かない
- 同じ人が両方で同じ選択肢に投票しても、1票と数える。単一選択で別々の選択肢に投票すると、それぞれに数える（1人の票を選べないため）
- 期間は時間単位なので、残りの時間を切り上げる。締め切りが少しずれる
- 締め切りを過ぎてから流した投票は作らず、本文に書く（止まっていた場合）
- 投票の文は保存しない。合計を書くときに Neplector から取る。控えるのは票の数だけ

**検討した選択肢**：

- 案A（採用）：合計の発言を更新する。途中でも全体が見える
- 案B（却下）：締め切りのあとに結果だけ出す。途中はサーバーごとの票しか見えない
- 案C（却下）：合計を出さない。サーバーごとに結果が違って見える

**確かめたこと**（2026-11-10）：Webhook で投票を作れ、選択肢の番号は順に 1, 2 と振られる（両方の投票で番号が合う）。Neplector は bot の発言の投票も記録するコードになっている。実際の票が写しから記録されるかは、本物の投票で確かめる。

## 判断5: リアクションした人の名前を、写しの末尾に書く（発案者）【判断7で廃止】

**決めたこと**：元の発言にリアクションした人の名前を、写しの本文の下に `-# 😀 太郎・花子` の形で書く。1つの絵文字につき5人まで、それ以上は「ほか n人」。人が変わったときだけ書き換える。設定 `show_reactors` で止められる。

**検討した選択肢**：

- 案A（採用）：写しの末尾に書く。すぐ作れて、チャンネルに発言が増えない
- 案B（却下）：加えて、元の発言の側にも別の発言で書く。両側で分かるが、リアクションのたびにチャンネルの下に発言が増えて、会話の邪魔になる
- 案C（却下）：メニューから確認する（押した人にだけ見せる）。編集済みの印も発言の増加も無いが、毎回の操作、Discord との常時接続、bot の招待し直しが要り、作る量も多い

**引き換え**：

- 写しに「編集済み」と出る
- 相手のサーバーで写しに付いたリアクションは、元の発言の側では誰のものか分からない。人の発言は bot が編集できない
- 投票の写しには書けない。投票は作った後に編集できない

**保存するもの**：名前は保存せず、書くたびに Neplector から取る。変わったかを見るためのハッシュだけを持つ。

## 判断6: 元の発言の側は、右クリックのメニューで見せる（発案者）

**決めたこと**：発言を右クリック（スマホは長押し）→「アプリ」→「リアクションした人」で、元の発言と写しの両方のリアクションを、絵文字ごと・サーバーごとの名前で、押した人にだけ見せる。元の発言でも写しでも使える。

**きっかけ**：判断5で、元の発言の側では相手のサーバーの誰がリアクションしたか分からないことが残っていた（人の発言は bot が編集できない）。

**検討した選択肢**：

- 案A（採用）：右クリックのメニュー。チャンネルに何も増えず、両方のサーバーで使える。コマンドの仕組み（ADR 0005）はもうある
- 案B（却下）：発言の下にスレッドを作って名前を書く。発言ごとにスレッドが増え、スレッドへの返事が同期されないようにする扱いも要る
- 案C（却下）：チャンネルに別の発言を出す。リアクションのたびにチャンネルの下に発言が増える

**引き換え**：見るたびに操作が要る。

## 判断7: 写しの末尾の名前をやめる。右クリックのメニューに、アイコンを付ける（発案者）

**決めたこと**：判断5（写しの末尾に名前を書く）をやめる。書いた写しは、次に動いたときに1回だけ、名前の無い本文に戻す。誰がリアクションしたかは、判断6のメニューで見る。メニューは1人ずつの欄にして、名前・アイコン・付けた絵文字・サーバーを出す（10人ごとのページ）。

**選んだ理由**（発案者）：写しの末尾の名前は、片方の向きでしか出ない。両方を見られる人にしか、全体が分からなかった。メニューなら、どちらのサーバーからも両方が見える。

**引き換え**：書いたことのある写しには「編集済み」の印が残る。

**その後の変更**（発案者）：1人ずつの欄（名前・アイコン・絵文字・サーバーの3行）は場所を取るので、絵文字ごとにまとめて、その下にサーバーごとの名前を並べる形にした。1つの欄に出せるアイコンは1人分だけなので、アイコンは出さない（発案者：アイコンは無くてよい）。

## 判断8: アイコンを bot 専用の絵文字にして、名前の前に出す（発案者）

**決めたこと**：「リアクションした人」の名前の前に、その人のアイコンを小さく出す。アイコンは bot 専用の絵文字（アプリの絵文字、最大2000個）として登録する。サーバーごとにアイコンが違うことがあるので、人とサーバーの組ごとに1つ。

- アイコンが変わったら作り直す
- Neplector から外れた人と、サーバーにいなくなった人の分は、忘れる処理（1時間ごと）で消す
- 手元に残すのは、絵文字の ID と、アイコンの URL のハッシュだけ
- 作れなかったときは、名前だけで出す

**検討した選択肢**：

- 案A（採用）：bot 専用の絵文字にする。絵文字ごとのまとまりを保ったまま、名前の横に小さく出せる。作る量はいちばん多い
- 案B（却下）：Discord の新しい表示部品（Components V2）で、右にアイコンを置く。1人1行になり、アイコンが大きめで場所を取る
- 案C（却下）：1人ずつの欄に戻す。3行になって場所を取る（判断7のあとに発案者が指摘）
- discord.py に替える：発案者が提案。表示の制約は Discord 自体の決まりで、ライブラリを替えてもできることは変わらないので、替えない

**引き換え**：アイコンの画像が、bot の持ち物として Discord に置かれる（bot からしか使えない）。サーバーにいなくなった人の分は、最大1時間残る。

## 判断9: 長いあいだ表示されていないアイコンの絵文字を消す（発案者の案を Claude が直した）

**決めたこと**：アイコンの絵文字は、最後に表示されてから 90日たったら、1時間ごとの整理で消す。また要るときは、その場で作り直す。日数は設定 `avatar_emoji_days` で変えられる。

**検討した選択肢**：

- 案A（採用）：最後に表示されてからの日数で消す。使われない分だけが減り、見た目は変わらない。アイコンの画像を Discord に置いておく期間も短くなる
- 案B（却下、発案者の最初の案）：サーバーに入ってからの年数で消す。長くいる人ほどよく表示されるので、消してもすぐ作り直しになる

**選んだ理由**：上限（2000個）には今の規模では届かないが、要らないものを持ち続けないため。

## 用語メモ

- スーパーリアクション：Discord の目立つリアクション。bot は普通のリアクションとして写す
