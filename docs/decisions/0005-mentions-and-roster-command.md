# 0005: 相手のサーバーの人へのメンションと、発言が写った人の名簿のコマンド

- 日付: 2026-11-10
- 状態: 一部置き換え（判断3 の `intents = 0` は [0010](0010-rebuild-on-discord-py-with-guilds.md) 判断2 で GUILDS だけに置き換え。ほかは採用中）
- 関連: [0001](0001-sync-scope-and-bot-permissions.md) 判断1（常時接続を使わない。この ADR で一部置き換え）、Neplector の ADR 0004（外れた人）

## 判断1: 相手のサーバーの人へのメンションを、本物の通知にする（発案者）

**決めたこと**：写しの中で、相手のサーバーにいる人は `<@ID>` のまま残す。通知するのは、元のサーバーにいない人だけ。両方にいる人は元のサーバーで通知済みなので、二重に通知しない。`@everyone` とロールは通知しない。引用の中と編集では通知しない。どちらのサーバーにもいない人は `@不明なメンバー` のまま。

**検討した選択肢**：

- 案A（採用）：通知する。相手のサーバーの人に呼びかけられる
- 案B（却下）：文字の `@名前` のままにする。呼ばれたことに気づけない

**引き換え**：相手のサーバーの人を呼ぶには、名簿の ID を見て `<@ID>` と書く。Discord の入力候補には自分のサーバーの人しか出ないため。元のサーバーの画面では、呼ばれた人の名前がうまく出ないことがある。

## 判断2: 名簿に載せるのは、写しが流れた人だけ（発案者）【[0007](0007-full-roster-with-hide.md) で置き換え】

**決めたこと**：`/nepsync-members` は、実行したチャンネルの組について、写しが流れた人の名前・ID・アイコン・見られるか・発言できるかを、実行した人にだけ見せる。写しが消えて対応が無くなった人と、外れた人は載らない。

**検討した選択肢**：

- 案A（採用）：写しが流れた人だけ。名前はもう相手のサーバーに見えているので、新しく知られることが少ない。追加の周知も要らない
- 案B（却下）：見られる人全員を載せる。まだ発言していない人にも呼びかけられるが、一度も発言していない人の名前が相手のサーバーへ見える。告知に名簿のことは書いていない
- 案C（却下）：運営者だけが使える。安全だが、ID を毎回運営者に聞くことになる

**引き換え**：まだ発言していない人は載らないので、相手のサーバーの新しい人には呼びかけにくい。

**権限の計算**：Neplector の名簿とロールの記録（`role_periods`）、bot が読むチャンネルの権限から計算する。Neplector の記録は最大30分遅れるので、ロールを変えた直後は古いことがある。

## 判断2a: 呼ぶための文字は、名簿の中にコードブロックで載せる（発案者）【[0014](0014-easier-cross-server-mentions.md) で置き換え】

**決めたこと**：名簿の人ごとの欄に、`<@ID>` をコードブロックで載せる。ボタンはページ送りだけにする。

**検討した選択肢**：

- 案A（採用）：名簿に直接載せる。一覧を見たらそのままコピーできる
- 案B（却下、いったん作って発案者の指摘でやめた）：人ごとのボタンを押すと別の返事で見せる。操作が1回増えて、一覧と行き来することになる

## 判断3: コマンドを受けるためだけに、知らせの無い常時接続を使う（Claude の案）

**決めたこと**：ADR 0001 判断1 の「常時接続を使わない」を変えて、`intents = 0` で接続する。受け取りを処理するのは `INTERACTION_CREATE` だけ。発言の知らせは Discord から届かない。同期とは別のスレッドで動かし、接続が切れても同期は止まらない。

**検討した選択肢**：

- 案A（採用）：`intents = 0` の常時接続。公開の住所が要らず、Linux に移しても同じ形で動く。`websockets` のライブラリが1つ要る
- 案B（却下）：HTTP でコマンドを受ける。常時接続は要らないが、インターネットから届く住所が要る。今の機械は公開していない

**守り**：テストで `intents` が 0 であることと、ほかの知らせを処理しないことを確かめる。

**引き換え**：bot がオンラインに見える。招待のし直しは要らなかった（2026-11-10 に、今の招待のまま両方のサーバーへ登録できた）。

## 用語メモ

- intents：bot が受け取る知らせの種類の指定。0 なら発言やメンバーの知らせは届かない
- ephemeral（一時的な返事）：実行した人にだけ見える返事
