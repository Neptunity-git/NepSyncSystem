# 0006: 添付の上限を 20 MiB に固定し、ファイル名を URL から引き継ぐ

- 日付: 2026-11-10
- 状態: 採用中（方針を変えたら、このファイルは書き換えず、新しい ADR を作ってここを「廃止（NNNN で置き換え）」にする）

## 判断1: 添付の上限は 20 MiB。ブーストされても上げない（発案者）

**決めたこと**：上限は Discord の標準と同じ 20 MiB。両方のサーバーの条件を同じに保つため、ブーストでは上げない。設定 `max_upload_bytes` の既定値にする。

**検討した選択肢**：

- 案A（採用）：20 MiB に固定する。どちらのサーバーからでも同じ大きさまで届く
- 案B（却下）：ブーストに合わせて上げる。向きによって届く大きさが変わる
- 案C（却下）：最初の 10 MiB のまま。送れるファイルが写らない

## 判断2: ファイル名は添付の URL から取る（Claude の案）

**決めたこと**：Neplector の `url` の最後の部分をファイル名にする。記録の拡張子と合わないときや、取れないときは `file0.png` の形にする。名前は保存しない。送信を壊す文字は `_` にする。

**検討した選択肢**：

- 案A（採用）：URL から取る。Neplector を変えずに、今ある全件（2026-11-10 に 1,972 件を確かめた）で取れる
- 案B（Neplector に依頼中）：Neplector に `title` を記録してもらう。日本語の名前も保てるが、Neplector の ADR 0036 と告知に関わる判断が要る

**残ること**：Discord は URL の名前を自分で書き換える。日本語は落ち、スペースは `_` になる（`議事録 2026.png` → `2026.png`。日本語だけの `議事録.png` は `f17df61cc7237989.png` のような文字列になる。2026-11-10 に確かめた）。元の名前は Discord の `title` にだけ残るが、Neplector は記録していない。

## 判断3: 日本語の名前は、Neplector への仕様変更の依頼で解決する（発案者）

**決めたこと**：Neplector の決まりと告知に関わるので、NepSync の側から Neplector を直接変えない。依頼は [requests/2026-11-10-neplector-attachment-title.md](../requests/2026-11-10-neplector-attachment-title.md)。

NepSync は先に対応した。`attachments[].title` が届けばそれを使い、無ければ URL から取る。どちらの順番で入っても動く。

**Neplector の対応（2026-11-10、Neplector ADR 0045）**：`attachments[].filename` として、02:14 より後に貼られたファイルから渡す（過去分は埋めない）。NepSync は title → filename → URL の順に使い、どれも無い古い添付は `file0.mp4` のように拡張子だけ合わせる。

**残る心配**：Neplector が記録しているのは Discord の `filename`。Webhook で確かめたかぎり、日本語は `filename` から落ちて `title` にだけ残る（判断2の表）。人の投稿でも同じなら、日本語の名前はまだ届かない。本物のファイルで確かめる。
