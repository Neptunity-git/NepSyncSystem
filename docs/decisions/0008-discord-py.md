# 0008: Discord とのやりとりを discord.py に移す

- 日付: 2026-11-10
- 状態: 一部置き換え（判断1 の段階2の進め方と、判断2 の専用のスレッドは [0010](0010-rebuild-on-discord-py-with-guilds.md) で置き換え。判断3 は採用中）
- 関連: [0003](0003-two-sites-and-always-on.md)（標準のライブラリだけで動かす。Discord の部分はこの ADR で置き換え）、[0004](0004-reactions-and-polls.md) 判断8（discord.py に替えない。この ADR で置き換え）、[0005](0005-mentions-and-roster-command.md) 判断3（`intents = 0` の常時接続。中身はそのまま、作りを discord.py にする）

## 判断1: discord.py を入れる。2段階で移す（発案者）

**決めたこと**：自前で書いていた Discord とのやりとりを、discord.py（2.7.1）に移す。

- 段階1：スラッシュコマンドを受ける常時接続（`gateway.py` を消して `bot.py`）
- 段階2：同期が使う Discord の REST（`clients.py` の `Discord`）

**検討した選択肢**：

- 案A（採用）：2段階で移す。段階1は同期の本体に触れないので、先に入れて様子を見られる
- 案B（却下）：一度に全部移す。変わる場所が多く、問題が出たときに原因を切り分けにくい
- 案C（却下）：今のまま自前で書く（0004 判断8）。できることは変わらないが、常時接続（心臓の鼓動・つなぎ直し）と回数制限の扱いを自分で保守し続けることになる。発案者の先輩からも、使うべきだと指摘があった

**選んだ理由**：できることは変わらない（Discord の決まりで決まる）が、壊れやすい部分（常時接続、回数制限）を、多くの人が使って直してきた部品に任せられる。他の人が読んでも分かりやすい。

**引き換え**：ライブラリが増える（discord.py と、その下の aiohttp など）。版を上げるときに、動きが変わっていないかを確かめる必要がある。

## 判断2: 答えの中身と、Discord への返事を分ける（Claude の案）

**決めたこと**：`commands.py` は答えの中身（文・埋め込み・ページ）を作るだけにして、Discord への返事は `bot.py`（discord.py）が送る。

- 時間のかかる処理（Neplector と Discord の REST、SQLite）は、専用のスレッド1本で順に動かす。discord.py の流れ（非同期）を止めると、心臓の鼓動が遅れて接続が切れるため。SQLite のつなぎはスレッドをまたげないので、そのスレッドで開く
- 名簿の「前へ」「次へ」は DynamicItem（custom_id の形で受け取りを決める部品）にする。custom_id の形は前と同じ（`nepsync-members:チャンネル:ページ`）なので、入れ替える前に出したボタンも効く。ボタンを覚えておかないので、記憶も溜まらない
- `/nepsync-hide`・`/nepsync-show` も、先に「考え中」を返してから答える。前は直接答えていたが、名簿を作っている途中だと3秒の決まりに間に合わないことがある

**検討した選択肢**：

- 案A（採用）：中身と返事を分ける。中身のテスト（名簿・リアクションの一覧）はそのまま使える
- 案B（却下）：全部を discord.py の書き方（非同期）で書き直す。段階1で同期の本体まで変わってしまう

## 判断3: discord.py のログは INFO 以上に限る（Claude の案）

**決めたこと**：discord.py の細かいログ（DEBUG）は出さない。discord.py は DEBUG のログに、送った中身（本文）と受け取った知らせをそのまま書くため（「会話の本文をログに書かない」の約束）。ログは `run.log` に流し、例外は種類だけ書く。音声の部品が無いという警告は、音声を使わないので出さない。

**守り**：テストで、DEBUG のログが書かれないこと、`intents` が 0 であること、答えが打った人にだけ見えて誰も呼ばないことを確かめる。

**後で見直す条件**：discord.py の版を上げるとき（INFO 以上のログに中身が出ていないかを確かめ直す）。

## 用語メモ

- 非同期（async）：待ち時間のあいだに別の仕事を進める書き方。discord.py はこの書き方が前提
- DynamicItem：ボタンなどの部品を、custom_id の形（正規表現）で見分ける discord.py の仕組み。再起動しても効く
- DEBUG・INFO：ログの細かさの段階。DEBUG が一番細かい
