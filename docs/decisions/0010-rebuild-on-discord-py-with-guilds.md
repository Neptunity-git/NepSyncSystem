# 0010: 同期の本体も discord.py で作り直す。GUILDS の知らせを受ける

- 日付: 2026-11-10
- 状態: 採用中（方針を変えたら、このファイルは書き換えず、新しい ADR を作ってここを「廃止（NNNN で置き換え）」にする）
- 関連: [0008](0008-discord-py.md) 判断1（段階2の進め方）・判断2（専用のスレッド）をこの ADR で置き換え、[0005](0005-mentions-and-roster-command.md) 判断3（`intents = 0`）をこの ADR で置き換え、[0001](0001-sync-scope-and-bot-permissions.md) 判断1（発言の知らせを受けない）・判断2（削除の守り）は変えない

## 判断1: 同期の本体も、discord.py の書き方で作り直す（発案者）

**決めたこと**：同期の本体（`engine.py`）を、discord.py の公開されている関数（`Webhook.send`、`channel.edit`、`guild.create_text_channel`、`channel.move` など）で作り直す。自前の REST の部品（`clients.py`）は消す。Neplector の API は aiohttp（discord.py が使っている通信の部品）で読む（`neplector.py`）。

**検討した選択肢**：

- 案A（採用）：全部を作り直す。規模が大きくないので、まとめて変えられる
- 案B（却下）：discord.py の内部の部品（`HTTPClient`）を、今の同期の本体から呼ぶ。公開されていない部品で、版を上げると黙って変わりうる。これでは discord.py を使う意味が無い（発案者が却下）
- 案C（却下）：同期は今のまま（標準のライブラリ）、コマンドだけ discord.py。段階1の形。Discord とのやりとりが2通りに分かれたまま残る

**引き換え**：テストも書き直しになった。偽物（`tests/fakes.py`）は discord.py の形をまね、呼ばれるたびに本物の関数と引数の形を照らし合わせる（名前の書き間違いや、本物に無い引数を見つける）。

## 判断2: GUILDS の知らせだけ受ける（発案者）

**決めたこと**：常時接続の `intents` を 0 から GUILDS だけにする。GUILDS で届くのは、サーバー・チャンネル・スレッド・ロールの形（名前、並び順、設定、権限の上書き）の知らせ。発言・リアクション・メンバーの知らせと、発言の中身（Message Content）は受けない。

**選んだ理由**：discord.py は、並べ替え（`move`）や権限の計算（`permissions_for`）で、GUILDS の知らせで保つ手元の控え（キャッシュ）を使う。0 のままだと控えが空で、並べ替えはエラーも出さずに何もしない。

**変わらないこと**：人の情報（発言・リアクション・票・名簿・忘れる知らせ）は、今までどおり Neplector だけから読む。外れた人の発言は bot に届かない。GUILDS で増えるのは「bot が管理する場所の形」で、前から REST で毎回聞いていたもの。

**検討した選択肢**：

- 案A（採用）：GUILDS だけ受ける
- 案B（却下）：0 のまま、控えを使わない関数だけ使う。並べ替えや権限の計算を自前で書き続けることになり、作り直す意味が薄れる
- 案C（却下）：形を Neplector から受ける。Neplector は位置・トピック・タグの ID・権限の上書きを持たない（人の情報を扱う場所で、形の控えは持たない決まり）。discord.py も自分の控えしか見ない

**守り**：テストで、`intents` が GUILDS だけであること（発言・リアクション・メンバー・Message Content が無いこと）を確かめる。

## 判断3: 同期の本体とコマンドを、1つの bot の中で動かす（Claude の案）

**決めたこと**：同期の本体とスラッシュコマンドを、1つの discord.py の bot の流れ（非同期）の中で動かす。つながってサーバーの控えがそろったら、同期の本体を始める。Neplector を長く待つあいだ（最大25秒）も、コマンドには答えられる。告知の「出す」「下げる」は、押されたらすぐ処理する（同期の本体と同時に動かないよう、順番待ちの鍵を使う）。

**引き換え**：Discord につながらないあいだは、同期も止まる（前はコマンドだけが止まった）。つながらないときは、discord.py がつなぎ直し続け、直らなければ bot を作り直してつなぎ直す。token の誤りのように直らないときは、プロセスを終える。

## 判断4: 「消えた」は、控えでなく Discord に直接聞いて確かめる（Claude の案）

**決めたこと**：チャンネルを消してよいかの確かめは、前と同じく Discord に直接聞いて（`fetch_channel`）、404・Unknown Channel のときだけ「消えた」とする。手元の控えに無いことは、消えたことの確かめにしない（つないだ直後や Discord の障害では、控えが空のことがある）。控えがまだ無いサーバーがあるときは、構造の見回りを後にする。ADR 0001 判断2 の守り（`channel.delete` の知らせだけで動く、404 の確認、1時間の上限）は変えない。

## 判断5: 並べ替えは、目標を先に控えに残してから、1つずつ動かす（Claude の案）

**決めたこと**：discord.py の `move` は1つずつ動かす。動かすたびに、手元の控えが知らせで追いつくのを待ってから（最大10秒）、次の1手を決める。目標の並びは先に SQLite に残し、途中で止まったら、次の回は同じ目標の続きをやる。

**選んだ理由**：双方向では、動かしかけの並びが「人が変えたもの」に見えて、元のサーバーに写し返してしまう（テストで確かめた）。

## 用語メモ

- intents：bot が受け取る知らせの種類の指定
- GUILDS：サーバー・チャンネル・スレッド・ロールの形の知らせ。発言やメンバーの知らせは入らない
- 控え（キャッシュ）：discord.py が手元に持っている、サーバーの形の写し。GUILDS の知らせで変わる
- 非同期（async）：待ち時間のあいだに別の仕事を進める書き方。discord.py はこの書き方が前提
