# 0012: ピン留めを両方向に写す

- 日付: 2026-11-14
- 状態: 採用中（方針を変えたら、このファイルは書き換えず、新しい ADR を作ってここを「廃止（NNNN で置き換え）」にする）
- 関連: [0001](0001-sync-scope-and-bot-permissions.md) 判断6（「メッセージの管理」を付けない。変えない）・[0010](0010-rebuild-on-discord-py-with-guilds.md) 判断2（GUILDS の知らせだけ。変えない）

## 判断1: ピン留めの付け外しを、元の発言と写しのあいだで写す（発案者）

**決めたこと**：同期した発言（元の発言と写しの組）のどちらかでピン留めが付いた・外れたら、もう片方も同じにする。双方向の設定なら、写しのピン留めも元の発言に写す。告知チャンネルの組は対象にしない。

**材料**：Neplector は発言ごとに `pinned`（ピン留め中か）を持ち、変わると `message.update` の行を流す。`/v1/messages` の答えにも入っている。Discord から新しい知らせを受ける必要は無く、GUILDS だけ・Message Content なし・本文を保存しない、は変わらない。

## 判断2: 前からピン留めされている発言は揃えない（発案者）

**決めたこと**：この機能を入れたあとに付け外しされたものだけを写す。入れる前のピン留めを一度に揃える処理は作らない。

**検討した選択肢**：

- 案A（採用）：これからの付け外しだけ。同期を始めたのは 2026-11-09 で、それより前の発言には写しが無いので、揃える対象はもともと少ない
- 案B（却下）：入れたときに一度だけ揃える。揃えるための処理と確認が増えるわりに、対象が少ない

**引き換え**：入れる前からピン留めされている元の発言は、あとで編集されると（`message.update` が来て、控えと違うので）そのときに写しもピン留めされる。困る動きではないので受け入れる。

## 判断3: 知らせが来た側の今の値を、控えと比べて写す。優先サーバーは使わない（Claude の案・発案者の了承）

**決めたこと**：発言の組ごとに「前回揃えたときのピン留め」を控え（`message_pairs.pinned`）に持つ。`message.update` が来た発言の今の値が控えと違えば、相手を同じにして控えを新しくする。控えと同じなら何もしない。

**選んだ理由**：

- bot が相手をピン留めした知らせも戻ってくるが、控えと同じなので何もせず、輪にならない
- ピン留めは「付いている／付いていない」の2つしか無いので、両方が控えから変わっていれば、必ず同じ値になっている。チャンネル名のように「両方で違う値に変わった」ことが起きないので、優先サーバー（`priority`）は要らない。続けて操作されたときは、後の操作が残る
- 相手側の値は見ない。Neplector が相手の記録をまだ新しくしていない一瞬に読むと、「相手が外された」と見誤って元の発言のピン留めを外してしまう。知らせが来た発言の記録は、その知らせと一緒に新しくなっているので信用できる

## 判断4: bot に「メッセージのピン留め」の権限を足す（Claude の案）

**決めたこと**：両方のサーバーの同期カテゴリで、bot に「メッセージのピン留め」（Pin Messages）を許可する。`doctor` で確かめる。一方通行のときは、書かない側には付けない。

**選んだ理由**：Discord はピン留めを「メッセージの管理」から別の権限に分けた（discord.py 2.7 の資料で確かめた）。ピン留めのために「メッセージの管理」を付ける必要が無いので、0001 判断6 は変わらない。

**引き換え**：

- bot がピン留めすると、相手のチャンネルに「NepSync がメッセージをピン留めしました」と Discord が自動で出す。消すには「メッセージの管理」が要るので残す。この自動の発言は `counted = 0` なので、相手に写らない
- 1つのチャンネルのピン留めは250件まで。上限で失敗したら、運営者に知らせる。権限が無くて失敗したときも知らせる

## まだ確かめていないこと

- ピン留めの付け外しで、Neplector に `message.update` が実際に来るか（Neplector のコードでは、`pinned` が変わると記録を新しくする）
- Webhook の写しをピン留めしたときにも、Neplector に知らせが来るか（来なければ、写し → 元の向きだけ動かない）

## 用語メモ

- 控え：前回そろえたときの値。今の値と比べて、どちらが変わったかを知るために使う
- 優先サーバー（`priority`）：両方のサーバーで同じ項目が別々に変わったときに、どちらの値に合わせるかの設定
