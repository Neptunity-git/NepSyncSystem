# 設計：全体の形

判断の理由は [ADR 0001](../decisions/0001-sync-scope-and-bot-permissions.md)、Neplector 側の材料は `../Neplector` の `docs/design/service-gaps.md` と、API の `/docs`（`https://neplector.<ドメイン>/docs`）。

## 全体図

```
 サーバーA ──記録──┐                         ┌── Webhook で投稿 ──> サーバーA / B
                   ├─> Neplector ──API──> NepSync
 サーバーB ──記録──┘   （読むだけ）          └── bot（REST）で構造を操作 ─> サーバーA / B
                                              ↕
                                        対応表（SQLite）
```

NepSync は3つの仕事を、1つのプログラムの中で別々に回す。

| 仕事 | 動くきっかけ | すること |
|---|---|---|
| 発言の同期 | `/v1/changes` の新着（ロングポーリング） | 発言・スレッドを相手に流す |
| 構造の同期 | `channel.*` の新着と、数分おきの見回り | 両方のカテゴリを見比べて、差を直す |
| 忘れる処理 | 1時間ごと | `/v1/forget` を見て写しを消す |
| リアクション | `reaction.*` の新着 | 元と写しの今の姿を見て、bot の分をそろえる |
| ピン留め | `message.update` の新着 | 知らせが来た発言のピン留めを控えと比べ、違えば相手を同じにする（ADR 0012） |
| 投票の合計 | `poll.vote.*` の新着と締め切り | 合計の発言を書き換える（最大で1分に1回） |
| 告知 | 右クリックのメニューで書かれた依頼（`announce_requests`） | 選ばれた告知を相手の告知チャンネルに写す・下げる（ADR 0009） |

`/v1/changes` を読むのは1か所だけにし、発言の行と `channel.*` の行に振り分ける。

## 発言の同期の流れ

1. `/v1/changes` の行を番号順に読む
2. その行のチャンネルが組になっていなければ捨てる（Neplector は同期しないカテゴリの変更も流してくる）
3. `message.create` で `counted = 1` のものだけ、`/v1/messages` で中身を取る。**無ければ流さない**（外れた人か、消された発言）
4. 名前を `member_servers` で引き、本文を書き換え（呼び出しを無効化、リンクの書き換え、返信の引用）、Webhook で投稿する。`wait=true` で写しの ID を受け取る
5. 対応を保存し、読んだ番号を進める

相手の Webhook の投稿は `counted = 0` で来るので、3で止まる。対応表にある写しの ID と `webhook_id` でも二重に確かめる。

**写しの ID を保存する前に止まると**、次回同じ発言を流して写しが重なる。Webhook に「同じものは1回だけ」の仕組みは無い。取りこぼしよりましなので受け入れ、投稿の直後に毎回保存して、起きる時間を短くする。

### スレッドは発言が作る

`thread.create` の行では何も作らない。人の発言が来たときに、相手のスレッドが無ければそこで作る。写しのスレッドの最初の発言は `counted = 0` なので、自分の作ったスレッドでは何も起きず、輪にならない。

## 構造の同期の流れ

イベントの内容をそのまま写さず、**今の姿を見比べて差を直す**。止まっていた間の変更も、自分の変更の知らせも、同じ処理で正しく扱える。

1. bot で両方のサーバーのチャンネル一覧を取る（`GET /guilds/{id}/channels`）。2026-11-16 から、bot に見えないチャンネルは一覧に出なくなる（Discord の資料）。**一覧に無いだけでは、消えたと判断しない**
2. Neplector の `channels` の表で、読んでいるチャンネルに絞る（要件の F3。運営者だけのチャンネルを写さないため）
3. 組ごとに、両方の値を「前回そろえた値」（控え）と比べる

| A | B | すること |
|---|---|---|
| 控えと同じ | 控えと同じ | 何もしない |
| 変わった | 控えと同じ | B に A の値を書く |
| 控えと同じ | 変わった | A に B の値を書く |
| 変わった | 変わった | 優先サーバーの値にして、運営者に知らせる |

書いたら控えを新しくする。次の知らせが来ても控えと同じなので、輪にならない。

**チャンネルを作るとき**は、作ったらすぐ組を保存する。途中で止まっても、次の見回りで同じ種類・同じ名前のものとして組になる。

**消すとき**は、`channel.delete` の行が来たら元のチャンネルを bot で確かめ（404 のときだけ）、上限（1時間に3つ）の中なら相手を消して、対応表からも消す。相手を消した知らせが来ても、対応がもう無いので何もしない。

## 保存するもの

SQLite のファイル1つ（`data/nepsync.db`。コミットしない）。**本文は入れない。**

| 表 | 中身 |
|---|---|
| `cursor` | `/v1/changes`・`/v1/forget` の読んだ番号 |
| `category_pairs` | カテゴリの組（ID） |
| `channel_pairs` | チャンネルの組、構造の控え（トピックを含む） |
| `webhooks` | チャンネルごとの Webhook の ID と token |
| `thread_pairs` | スレッドの組 |
| `message_pairs` | 元の ID、写しの ID、書いた人の ID、スレッド、Webhook、編集の時刻、ピン留めの控え（ADR 0012） |
| `bot_reactions` | bot が付けたリアクション（発言の ID と絵文字） |
| `roster_hidden` | 名簿に載せない人の ID（ADR 0007） |
| `reactor_lines` | やめた機能（写しの末尾の名前）で書いた写し。後片付けが済むと空になる |
| `poll_tallies` | 合計の発言の ID、票の数、更新の時刻。投票の文は入れない |
| `announce_requests` | 告知を出す・下げる依頼（発言の ID・チャンネルの ID・結果の記号・写しへのリンク）。1日で消す（ADR 0009） |
| `delete_log` | 自動で消した記録（上限の計算と、後で確かめるため。チャンネル名は入れず ID だけ） |

`message_pairs` の書いた人の ID は、外れた人の写しを消すために要る。トピックは人が書く文だが、会話の本文ではなくチャンネルの設定なので控えに持つ。

## コードの分け方

`work/nepsync/` に置く。通信を偽物に置き換えられる形にして、まわりのロジックを架空データでテストする（`work` で `python -m unittest discover -s tests -t .`）。

| ファイル | 役割 |
|---|---|
| `neplector.py` | Neplector の API（aiohttp）。503・429 は一時的な失敗として、やり直す |
| `store.py` | SQLite の対応表 |
| `rewrite.py` | 本文の書き換え（呼び出し、リンク、引用、2000文字の制限）。通信しない |
| `structure.py` | 見比べて、することを決める（discord.py のチャンネルを読むだけ）。通信しない |
| `engine.py` | 変更の処理、発言・スレッド・構造・削除・忘れる処理の実行。Discord への書き込みは discord.py の関数（ADR 0010） |
| `config.py` | 秘密の値（環境変数、無ければ `.env`）と `data/nepsync.toml` を読む |
| `bot.py`・`commands.py` | discord.py の bot（GUILDS の知らせだけ受ける）。この中で同期の本体とスラッシュコマンドが動く（ADR 0010）。`commands.py` は名簿・リアクションした人・投票した人（ADR 0011）の一覧・告知の依頼の答えの中身。告知は依頼を SQLite に書き、同期の本体がすぐ写す（ADR 0009） |
| `__main__.py` | コマンド：`doctor`（確かめる）・`plan`（することを見るだけ）・`run`（動かす）・`approve-deletes` |

同期の本体は1本の流れで順に処理する（同時に動かさない）ので、自分が作ったチャンネルの知らせと保存が前後することはない。チャンネルの形は discord.py の手元の控え（GUILDS の知らせで保たれる）から読み、「消えた」の確かめだけは Discord に直接聞く（ADR 0010 判断4）。

## bot の権限

bot はサーバーに権限なしで招き、同期カテゴリの権限の上書きで次を許可する。一方通行にするときは、書かない側を View Channel だけにする（ADR 0002）。

| 権限 | 使う場面 |
|---|---|
| View Channel | チャンネルの操作に必要 |
| Manage Channels | 作成・変更・削除・タグ |
| Manage Webhooks | チャンネルごとの Webhook を作る |
| Create Public Threads | テキストチャンネルのスレッドを作る |
| Manage Threads | スレッドの題名・アーカイブ・ロックを変える |
| Send Messages in Threads | 同上。これが無いと本番で 403（50001）になった（2026-11-09 に確かめた） |
| Read Message History | リアクションを付ける（ADR 0004）。Message Content が無いので本文は届かない |
| Add Reactions | まだ誰も付けていない絵文字を付ける（ADR 0004） |
| Pin Messages | ピン留めを写す（ADR 0012）。「メッセージの管理」とは別の権限 |

**付けないもの**：Manage Messages（写しは Webhook で編集・削除する。ADR 0001 判断6）、Administrator、Manage Roles。

サーバーの2FA必須の設定が有効だと、bot のオーナーにも二段階認証が要る（Manage Channels・Manage Webhooks・Manage Threads が対象。Discord の資料）。

## 順番

1. 通信しないロジックと偽物でのテスト（できた）
2. 実物の Discord と偽の Neplector で本体を通す（できた。2026-11-09）
3. 本番の `Nep共同企画` から実験用のサーバーへの一方通行で、本物の発言の流れを確かめる（できた。ADR 0002）
4. KGU_Neptunity と CID_Neptunity の双方向に切り替え、常時動かす（ADR 0003。動かし方と、IdeaPad の VM への移し方は [operations.md](operations.md)・ADR 0013）

## 実機で確かめること

### 確かめたこと（2026-11-09。本番と実験用のサーバーの `test` カテゴリで）

本番のサーバーは `@everyone` に権限が無いので、bot の権限はカテゴリの上書きだけになる。こちらの結果を基準にする。実験用のサーバーは `@everyone` に多くの権限があり、同じ確認にならない。

| 確かめたこと | 結果 |
|---|---|
| 常時接続せずに、チャンネルと Webhook を操作できるか | できる |
| カテゴリの上書きだけで、中のチャンネルを作成・変更・削除、並び順の変更、カテゴリ名の変更ができるか | できる |
| 作ったチャンネルが、カテゴリの上書きを引き継ぐか | 引き継ぐ |
| 中身が空のカテゴリが一覧に出るか | 出る（2026-11-16 の仕様変更のあとに、もう一度確かめる） |
| テキストのスレッド作成、フォーラムの投稿とタグ付き作成、スレッドの削除 | できる |
| Webhook の投稿・編集・削除、サイレント、呼び出しの無効化、隠す画像の添付 | できる |
| スレッドの題名・アーカイブ・ロック・タグの変更 | できる。Send Messages in Threads が要る |
| 同期本体を通した動き（作成、発言、返信、編集、添付、スレッド、フォーラム、削除の守り、外れた人の写しの削除） | できる（架空の発言。本番には書き込まない） |
| アーカイブ済みのスレッドへの Webhook の投稿 | できる。スレッドは自動で開く |
| 見えないチャンネルと消されたチャンネルの区別 | できる。見えない：403（コード 50001）、消された：404（コード 10003） |

### まだ確かめていないこと

| 確かめること | 違ったときの影響 |
|---|---|
| 告知の写しで、Webhook から `member` ロールの通知が鳴るか（ADR 0009） | 鳴らなければ、相手の告知チャンネルで bot に「@everyone、@here、全てのロールにメンション」を許可するか、ロールを誰でもメンションできるようにする |
| 告知のメニューを押したときに届く本文が、`run.log` に出ていないか | 出ていたら、ログの絞り方を見直す |
| 外部の絵文字とリンクの展開が、`@everyone` に権限の無いサーバーへの Webhook の投稿で動くか | 表示だけの問題。絵文字の対応を次の版で考える |
| Webhook の投稿が実際に `counted = 0` になるか（Neplector ADR 0035 判断7 でも未確認） | 輪の防ぎ方を見直す |
| チャンネルを消したときに `channel.delete` が来るか、カテゴリ外への移動が `channel.stop` になるか | 削除の判断の材料を見直す |
| 相手の上限を超える添付の、Discord の答え | F14 の扱いを見直す |
| Neplector が写しへのリアクションと票を記録するか（コードではする） | リアクションと合計が片方向になる |
| カスタム絵文字のリアクション（`name:id`）を実物で付けられるか | F21a を見直す |
| ピン留めの付け外しで、Neplector に `message.update` が来るか。写し（Webhook の発言）でも来るか（ADR 0012） | 来なければ、ピン留めは写らない（写しで来なければ、写し → 元の向きだけ） |
