# 要件定義：NepSyncSystem

> このファイルは常に最新版のみを保持する（過去の変更履歴は残さない）。
> 決定の経緯・理由は [decisions/](decisions/) のADRを参照。

## 機能要件

### 対象

- F1. 設定に書いたカテゴリ名を、両方のサーバーで探して組にする。組にしたあとは ID で固定し、名前が変わっても組は切れない
- F2. カテゴリの中のテキストとフォーラムだけを同期する。アナウンス・メディアは組にせず、運営者に知らせる（告知チャンネルは F2a）
- F2a. 設定に書いた告知チャンネルの組では、自動では流さない。発言の右クリック →「アプリ」の「相手のサーバーにも出す」で選んだ告知だけを写し、「相手のサーバーから下げる」で写しだけを消す。使えるのは、そのチャンネルで「メッセージの管理」を持つ人と、告知を書いた本人。写したあとの編集・削除・リアクションは同期チャンネルと同じ。告知の中の `announce_ping_roles`（`member`）のロールは、相手の同じ名前のロールで通知する。相手のサーバーで開けないリンク（同期されていない発言・同期していないチャンネルへのリンク）があれば、出したあとの答えで警告する。Discord のフォローは使わない（[ADR 0009](decisions/0009-announcements-by-menu.md)）
- F3. 同期の元にしてよいのは、Neplector が読んでいるチャンネル（`channels.reading = 1`）だけ。bot に見えていても、`member` に見えないチャンネルは写さない

### 構造の同期（双方向）

- F4. 新しいチャンネルができたら、相手のカテゴリに同じ種類・同じ名前で作り、Webhook も作る
- F5. **同じ種類で同じ名前**のチャンネルがすでに相手にあれば、新しく作らず組にする。テキストの `test` とフォーラムの `test` は別のものとして扱う。種類も名前も同じものが複数あれば組にせず、運営者に知らせる
- F6. 名前・トピック・並び順・低速モード・年齢制限・フォーラムのタグ・カテゴリ名の変更を、相手に反映する。両方で同じ項目が変わっていたら、設定で決めた優先サーバーの値にして、運営者に知らせる
- F7. チャンネルが消されたら、相手のチャンネルも消す。消す前に bot で Discord に聞いて「無い」（404）と確かめる。`channel.stop`（読むのをやめた）や権限の問題では消さない
- F8. 短い時間に一定数を超えて消されるときは、超えた分を消さずに止め、運営者の確認を待つ（既定：1時間に3つまで）
- F9. カテゴリが消されたときは、中のチャンネルを消さず、運営者に知らせる（Discord でもカテゴリを消しただけではチャンネルは残る）
- F10. 権限は同期しない。作ったチャンネルは相手のカテゴリの権限を引き継ぐ

### 発言の同期（双方向）

- F11. 人の発言（`counted = 1`）だけを流す。`webhook_id` のある発言と、自分の写しの ID は流さない
- F12. 投稿者の名前とアイコンは、元のサーバーの `member_servers` の値を使う
- F13. 編集・削除を写しに反映する。写しが消されても元の発言は消さない（対応だけ消す）
- F14. 添付は取得して送り直す。`spoiler` なら隠す。上限は 20 MiB に固定し、サーバーのブーストでは上げない。超えるものは送れないことを本文に書く。ファイル名は添付の URL から引き継ぐ（[ADR 0006](decisions/0006-attachment-limit-and-names.md)）
- F15. 返信は引用とリンクで表す。相手が写しへの返信なら、対応表で元の発言までたどる
- F16. `@everyone` とロールでは通知しない（告知の `member` だけは F2a）。相手のサーバーにいる人へのメンションは本物のメンションとして残し、元のサーバーにいない人にだけ通知する。どちらにも当たらない人は名前の文字にする。引用の中と編集では通知しない
- F17. サイレントとリンク展開を隠す印を写す
- F18. 本文の中の、組になったチャンネル・発言へのリンクを、相手側のものに書き換える。それ以外のリンクはそのまま
- F19. フォーラムの投稿は Webhook で作り、タグは名前で対応させる。テキストチャンネルのスレッドは bot で作り、Webhook で投稿する
- F20. スレッドの題名・タグ・アーカイブ・ロックの変更を相手に反映する
- F21. 転送は引用の形で流す。スタンプは中身を再現せず、そのことを本文に書く
- F21a. リアクションを両方向に写す。bot が同じ絵文字を1回付けるので、人数は同じにならない。その絵文字の人が元からいなくなったら、bot の分も外す。カスタム絵文字は名前で対応させ、相手に無いものは写さずに運営者に知らせる。発言の右クリックのメニュー「リアクションした人」で、両方のサーバーの人の名前を、絵文字ごと・サーバーごとにまとめて、押した人にだけ見せる
- F21b. 投票を相手にも作る。両方のサーバーに合計の発言を1つずつ出し、票が変わったら書き換える（最大で1分に1回）。締め切りを過ぎたら最後に1回書く。書くのは票の数だけで、誰が投票したかは書かない。投票の文は保存しない
- F21c. ピン留めの付け外しを両方向に写す（一方通行なら元から写しへだけ）。入れる前からのピン留めは揃えない。告知チャンネルの組は対象外。権限が無い・上限（250件）のときは運営者に知らせる（[ADR 0012](decisions/0012-pin-sync.md)）
- F22. 止まっていた間の発言は続きから流し、一定時間（既定：10分）より遅れたものに、元の時刻の印を付ける
- F23. 初めて動かすときは `last_seq` から始め、過去の発言は流さない

### 外れた人と消された発言

- F24. `/v1/forget` を1時間に1回見て、外れた人の写し・消された発言の写し・スレッドの写しを消し、対応表からも消す。Webhook が消されていて写しを消せないときは、消せなかった写しの ID を運営者に知らせる

### 運営

- F25. `doctor` コマンドで、API キー、両サーバーの bot の権限、カテゴリの組、Neplector が両方のカテゴリを読んでいるか、本文が開いているかを確かめる
- F25a. スラッシュコマンド `/nepsync-members` で、相手のサーバーにだけいて、そのチャンネルを見られる人（bot を除く）を、アイコンと名前の格子の画像で、実行した人にだけ見せる。並びは ★ → 最近選んだ人 → このチャンネルで最近発言した人 → 名前順。`名前:` の欄で探せる。メニューで選ぶと（10人まで。選び足せる）、名簿の発言の本文を、呼ぶための `<@ID>` だけに書き換え（スマホは長押しでコピー）、その下の枠に同じものをコードブロックで置く（PC はここからコピー）。1人のときは ★ のボタンを出す。写しの長押しのメニュー「この人を呼ぶ」でも出す。写しに返信すると、元の人に通知する。`/nepsync-hide`・`/nepsync-show` で、自分を載せない・載せるに戻す（[ADR 0007](decisions/0007-full-roster-with-hide.md)・[ADR 0014](decisions/0014-easier-cross-server-mentions.md)）
- F26. 運営者への知らせは、同期カテゴリの外の Webhook（設定）に送る
- F27. 設定の切り替えで、発言と構造を別々に止められる。削除だけを止めることもできる

## 非機能要件

- N1. 会話の本文を保存しない。手元に残すのは ID の対応、構造の控え、読んだ位置だけ。ログにも本文を書かない
- N2. bot は Discord の常時接続で発言の知らせを受けない（`intents = 0`。接続はスラッシュコマンドのためだけ）。特権の Message Content を有効にしない
- N3. 503・通信の失敗・Discord の 429（送りすぎ）で止まらず、待ってやり直す。止まっても続きから読める
- N4. 同じ処理が2回走っても壊れない。ただし、投稿の直後で対応を保存する前に止まると、写しが1回重なることがある。取りこぼしよりましなので受け入れる
- N5. 輪にならない。構造は「控えとの差」だけを反映するので、自分の変更の知らせを受けても何もしない
- N6. テスト・コミット・Qwen の作業場所に実データを入れない。テストは架空の会話で書く
- N7. API キー、bot の token、Webhook の URL をコミットしない
- N8. API の量の知らせの目安（1時間に本文5,000件・10万行）を、ふだんの動きで超えない
- N9. 常時動かす。同じ data のフォルダで2つ動かさない。止まっても続きから読み、想定していない失敗でも落ちずに知らせる
- N9a. スラッシュコマンドの失敗や切断で、同期を止めない
- N10. OS に依存しない。起動の設定だけが Windows と Linux で違い、動いている状態は `.env`、`data/nepsync.toml`、`data/nepsync.db` の3つだけ

## 未解決事項

- 2000文字を超える発言（Nitro は4000文字まで書ける）は、今は末尾を削る。分けて投稿するかは使ってから決める
- 本番で動かす機械。今は Windows の PC から、公開された API（`https://neplector.<ドメイン>`）を読んで動かしている（2026-11-16 から）。移す先は IdeaPad の VM の中のコンテナ（[ADR 0013](decisions/0013-move-to-container-in-vm.md)、[design/operations.md](design/operations.md)）。VM ができるのを待っている
- 実機で確かめること：[design/overview.md](design/overview.md) の「まだ確かめていないこと」
